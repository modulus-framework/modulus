# Compatibility

Modulus supports **.NET 8** and **.NET 10**. Every library package is built for both
target frameworks, so one package works in either runtime.

## Target frameworks

| Component | `net8.0` | `net10.0` | Notes |
|-----------|:--------:|:---------:|-------|
| Core, Data, Identity, Messaging, Platform, Observability libraries (`Synvro.Modulus.*`) | Yes | Yes | Both targets in every package |
| Realtime (`Synvro.Modulus.Realtime`, `.Redis`) | Yes | Yes | SSE is implemented without .NET 10-only APIs |
| UI packages (`Synvro.Modulus.Ui.*`, `AspNetCore.Mvc`, `Blazor`, ...) | No | Yes | Ship separately from the framework |
| CLI (`Synvro.Modulus.Cli`) | No | Yes | A .NET 10 dotnet tool |
| Apps generated by `modulus app` | No | Yes | Generated projects target `net10.0` |

Because a package contains both `lib/net8.0` and `lib/net10.0`, NuGet picks the right
assembly for your project automatically. Nothing needs to change in your code to move between the two.

## SDKs

- **Building this repository:** .NET SDK **10.0.109** or newer (`global.json` rolls forward to the newest 10.0 feature band).
- **Consuming the packages in a .NET 8 app:** the .NET 8 SDK and runtime are sufficient.
- **Running the test suite on .NET 8:** install both SDKs. The unit tests run on both targets by default.

## Choosing a target

| Your situation | Recommendation |
|----------------|----------------|
| New project, want the longest support window | `net10.0` |
| Existing .NET 8 application | Stay on `net8.0`; the libraries support it |
| Use the `modulus` CLI to scaffold | `net10.0` (the generated app targets it) |

## Testing both targets

```bash
dotnet test modulus.slnx --filter "Category=Unit"                  # net8.0 and net10.0
dotnet test tests/unit/Modulus.Core.Tests -p:ModulusTestTfm=net8.0  # one target only
```

## Support policy

Modulus follows [Semantic Versioning](https://semver.org/). A change that drops a target framework is a
major version change. Release notes are in the
[changelog on GitHub](https://github.com/modulus-framework/modulus/blob/main/CHANGELOG.md).
