# Compatibility

Modulus supports **.NET 10** only. Every library, the CLI and every generated app target `net10.0`.

## Target frameworks

| Component | Target |
|-----------|--------|
| Core, Data, Identity, Messaging, Platform, Observability libraries (`Synvro.Modulus.*`) | `net10.0` |
| Realtime (`Synvro.Modulus.Realtime`, `.Redis`) | `net10.0` |
| UI packages (`Synvro.Modulus.Ui.*`, `AspNetCore.Mvc`, `Blazor`, ...) | `net10.0`, shipped separately from the framework |
| CLI (`Synvro.Modulus.Cli`) | `net10.0` dotnet tool |
| Apps generated by `modulus app` | `net10.0`, pinned to the .NET 10 SDK band by `global.json` |

## SDKs

- **Building this repository and using the packages:** .NET SDK **10.0.109** or newer (`global.json` rolls forward to the newest 10.0 feature band).

## Existing applications on another framework

Modulus supports only `net10.0`. An application that targets another framework must move to `net10.0` (and its packages to the 10.x
line) before upgrading Modulus. The CLI refuses to work on an app whose `Directory.Build.props` targets anything else, and names the target to move to.

## Testing

```bash
dotnet test modulus.slnx --filter "Category=Unit"   # net10.0
```

## Support policy

Modulus follows [Semantic Versioning](https://semver.org/). A change that drops a target framework is a
major version change. Release notes are in the
[changelog on GitHub](https://github.com/modulus-framework/modulus/blob/main/CHANGELOG.md).
